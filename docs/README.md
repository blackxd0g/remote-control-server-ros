Начинать с состояния и нужной цели. По ходу работы обновлять журнал; при изменении цели — карту, при новом согласованном решении — решения. Спецификации оставлять в тематических документах, сведения о поставках — в `release-*.md`. Правила исполнения: [AGENTS.md](../AGENTS.md) и родительский AGENTS.md общего workspace.

Не помещать секреты и сырые дампы в проектную память. Markdown-журнал отражает разработку и не заменяет runtime-аудит приложения. Исторический архив сохранён без правок; его ссылки разрешаются относительно прежнего каталога `docs`, сведения могут быть устаревшими. Архив не следует автоматически включать в будущую публикацию без проверки содержимого.
