Рабочая архитектура REL-02 описана в [контракте](relay-control-development.md). Это локальное техническое решение с открытыми критериями приёмки, не подтверждение готовности к production.

2026-09-07, техническое решение REL-OPS-01 в рамках локальной разработки: сохранять отвергнутые события прежнего поколения в ограниченном общем объёме карантина, а защиту от replay при уплотнении истории — в бессрочных компактных записях. Это не новая политика удаления production-данных. Обоснование, миграция snapshot и границы — [эксплуатационный контракт](relay-operations.md).

2026-09-07, REL-OPS-02: пользователь подтвердил обслуживание карантина и локальные испытания надёжности. Технический порядок очистки — точная ревизия, подтверждение администратора, постоянный аудит намерения, fsync резервного файла на relay, затем освобождение очереди. Неизвестный результат и границы отката описаны в [контракте](relay-quarantine-maintenance.md).

DEC-006 / 2026-09-07: пользователь указал пока не проверять ARM64. Текущие проверки ограничены amd64; ARM64 сохраняется как отложенная цель REL-ARM64 до нового указания. Это не удаление поддержки архитектуры и не изменение исторических результатов релиза 2.2.1.

DEC-007 / 2026-09-09: пользователь явно разрешил публикацию сборки в Docker Hub и GitHub и исправление ошибок GitHub. Для REL-PUB-01 это заменяет запрет публикаций DEC-003; production deployment и изменение видимости relay не разрешены. Ограничение ARM64 DEC-006 сохраняется. До завершения PAR-01 выпуск оформляется предварительным, стабильный latest сохраняется.
