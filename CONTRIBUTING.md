# Разработка Remote Control Server

## Продолжение работы

Прочитать [AGENTS.md](AGENTS.md), родительские инструкции общего workspace и [индекс документации](docs/README.md). Сверить состояние, карту, решения и последний журнал с рабочими файлами. Согласованную цель записать до реализации, результаты — в журнал. Не сбрасывать незавершённые изменения.

## Окружение

Версии ниже взяты из текущих файлов проекта, а не означают проверку всех возможных комбинаций ОС и инструментов.

| Компонент | Требование / источник |
|---|---|
| Go | `go 1.26` в [go.mod](art-api/go.mod); Docker использует 1.26.7 |
| Rust | edition 2024, минимальная заявленная версия 1.89 в [Cargo.toml](Cargo.toml); Docker проверяет на 1.98.0, нужны rustfmt/clippy |
| Web | Node 24 как в Docker; pnpm 11.19.0 из [package.json](art-web/package.json), существующий pnpm-lock.yaml |
| Linux-сборка | Docker Desktop с Linux engine и Buildx либо Linux/WSL с нужными компиляторами; для musl — соответствующий target и linker |

Не заменять pnpm-lock.yaml другим менеджером пакетов. Первичная установка зависимостей может обращаться к сети. Не обновлять зависимости просто ради запуска проверки.

## UI и API локально

Следующие команды — PowerShell. Начальная папка каждого блока указана явно. Проверять код завершения каждой команды; при ошибке не продолжать сборку зависимого компонента.

Из `Remote Control Server/art-web`:

```powershell
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm run build
```

Vite записывает результат в `art-api/internal/webui/dist`; API встраивает этот каталог через go:embed. Поэтому UI нужно собрать до API. Не очищать каталог вручную для устранения ошибки сборки.

Из `Remote Control Server/art-api`, в отдельном терминале, с чистыми переменными окружения для локальной SQLite:

```powershell
$env:RDS_DATA_DIR = Join-Path (Split-Path (Get-Location).Path) 'work/local-api-data'
$env:RDS_API_LISTEN = '127.0.0.1:21114'
$env:RDS_DB_DRIVER = 'sqlite'
Remove-Item Env:ART_DB_DSN, Env:RDS_DB_DSN -ErrorAction SilentlyContinue
go run ./cmd/art-api
```

Использовать только отдельную локальную папку данных. Не подставлять production DSN, тома, секреты или резервные копии. При наличии ранее заданных ART_* или RDS_* настроек проверить их назначение без вывода секретных значений. Загрузчик отдаёт приоритет RDS_* перед совместимыми ART_*; этот пример использует RDS-переменные. Bootstrap-данные находятся в локальном секретном файле, заданном конфигурацией; не копировать их в чат/журнал. Остановка — Ctrl+C, данные остаются.

Для разработки UI из `art-web` в другом терминале:

```powershell
pnpm exec vite --host 127.0.0.1
```

Открыть локальный адрес из вывода Vite. `/api` и `/healthz` проксируются на `127.0.0.1:21114`. Этот режим запускает UI/API; HBBS/HBBR и совместимость официального клиента проверяются отдельно.

## Локальный контейнер

Из корня серверного проекта, с работающим Linux Docker engine:

```powershell
docker buildx build --platform linux/amd64 --load -f docker/all-in-one.Dockerfile -t remote-control-server:local-dev .
```

Это сборка текущих исходников в локальный тег, без публикации. `--load` здесь предназначен для одной архитектуры. ARM64 требует отдельной сборки и проверки; amd64 не подтверждает ARM64.

Не использовать `deploy/compose.all-in-one.yaml up` как доказательство запуска новой разработки: текущий файл указывает образ 2.1.1 и публикует сервисные порты. Для REL-02 следовать контракту [relay-control-development.md](docs/relay-control-development.md) и инструкции отдельного relay; не смешивать gateway и legacy-режимы. Полный локальный стенд REL-02 ещё имеет открытые критерии приёмки.

## Перед завершением задачи

Выполнить соответствующие [проверки](docs/testing.md), просмотреть изменённые файлы и исключить секреты/локальные данные. В журнале указать фактические результаты, пропуски и ограничения; обновить состояние и статус цели. Изменение документации не требует повторного полного прогона runtime-тестов.

Для нового чата достаточно указать AGENTS.md и docs/README.md и назвать цель. Перед передачей сохранить в project-state.md незавершённую работу и следующий шаг, в журнале — проверки. Не создавать вторую копию дорожной карты или отдельную противоречащую сводку.
